## 2026-10-07 · Q3 哨兵网格移动（SentryGrid）

- **AI 助手**：豆包（Doubao）桌面端（网页/客户端会话，会话标题"电子设备软件应用问题"）
- **任务**：补全 `SentryGrid` 的四个 TODO 方法——`current_pos.setter`（位置校验）、`move_forward`（前进/碰撞/耗电/断电）、`turn_left`、`turn_right`（原地转向，不耗电）
- **使用方式**：用户在豆包会话中粘贴 Q3 题面与骨架代码，AI 分两轮给出实现（第一轮基于题面假设的属性名，第二轮按用户贴出的实际骨架适配）；随后在豆包内讨论"撞墙是否耗电"的题面歧义、由 AI 起草英文/中文论坛澄清帖、并修复粘贴代码后出现的装饰器语法报错；提交前用户人工审查语义后落地。

### 豆包生成过程中出现、人工审查后修正/确认的问题

1. **初版属性名与骨架不匹配**：AI 第一轮实现假设位置存于 `self._current_pos`、直接读写 `self.fuel` 等只读 property；用户贴出实际骨架后确认应为 `self._pos`、`self._fuel` / `self._facing` / `self._collision_count`（私有变量），第二轮按骨架适配；
2. **边界检查重复实现**：初版手写 `nx < 0 or nx >= width` 等判断，骨架已提供 `is_blocked(x, y)`（障碍+越界一步到位）→ 改为复用；
3. **`@current_pos.setter` 装饰器报错**：粘贴代码后 IDE 报 `Expected function or class declaration after decorator`，根因是上方 `@property` getter 缺失或缩进混乱 → 整段（getter + setter + 三个方法）统一用 4 空格重写后消除；
4. **"撞墙是否耗电"题面歧义**：规范 3"前进消耗 1 单位电量"未注明"成功才消耗"，规范 4 使用"前进尝试"措辞——与豆包讨论后采用"任何前进尝试都耗电（含碰撞）"实现（`self._fuel -= 1` 在碰撞判断之前），并同步在课程讨论区发布澄清帖征求确认；若批改方隐藏测试按"仅成功移动耗电"实现，需把耗电语句移入成功移动分支。

### 最终实现要点（与题面规范逐条对应）

- `current_pos.setter`：仅接受长度为 2 的 tuple/list，否则抛 `TypeError`；元素转 int 后以 tuple 存 `self._pos`；
- `move_forward`：`fuel <= 0` 时底盘断电直接返回原位；计算前方格（`facing.delta` 位移），任何前进尝试消耗 1 电量；前方为障碍或越界（`is_blocked`）→ 位置/朝向不变、`collision_count` +1；可通行则经 setter 更新位置；
- `turn_left` / `turn_right`：按映射字典（UP→LEFT→DOWN→RIGHT 逆时针 / UP→RIGHT→DOWN→LEFT 顺时针）更新 `self._facing` 并返回新朝向，不耗电。
