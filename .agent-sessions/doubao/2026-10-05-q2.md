## 2026-10-05 · Q2 战斗日志分析（analyze_damage_log）

- **AI 助手**：豆包（Doubao）桌面端（网页/客户端会话）
- **任务**：实现 `analyze_damage_log(lines)`——解析混合格式伤害日志（传感器行 / JSON 行 / 脏行），返回固定契约统计字典
- **使用方式**：由用户在豆包会话中提出 Q2 需求，豆包生成初版实现；用户在豆包内逐条核对题面规范并理解代码逻辑；提交前再次人工审查，发现并修复以下问题后本地测试全绿

### 豆包初版存在、提交前人工修正的 4 处问题

1. **返回键名不符合契约**：初版返回 `total_damage` / `average_damage`，题面契约为 `total` / `avg`（可见测试 `KeyError: 'total'` 暴露）→ 改为契约键名；
2. **`return` 缩进错误**：统计汇总与 `return` 写在 `for line` 循环体内，只处理首行就提前返回 → 移到循环外；
3. **传感器行重复累加**：多段行（如 `F:32,L:5,R:12`）在解析每一段时都把已解析段落再累加一遍（front 被重复计数）→ 改为整行校验通过后统一累加；
4. **damage 边界**：初版用 `damage < 0` 放行 `damage = 0`，题面要求"严格正整数" → 改为 `damage <= 0` 按脏行跳过。

### 最终实现要点（与题面规范逐条对应）

- 两种有效行：传感器行（`F/L/R` 段允许缺失）、JSON 行（`armor` 三部位之一、`damage` 严格正整数）；
- 脏行（空行 / `#` 注释 / 缺字段 / 字段非法）一律跳过，全程不抛异常；
- 带 `id` 的 JSON 行按 id 去重（同 id 只计第一次）；
- 输出契约：`{"total", "by_armor", "most_hit", "avg"}`，`by_armor` 三键恒存在，无有效事件时 `most_hit=None`、`avg=0.0`。
